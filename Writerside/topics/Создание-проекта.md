# Создание проекта

Для создания проекта используйте команду:

```Bash
slinn-admin create-project www
```

> Все дальнейшие действия будут выполняться в папке проекта

www - название папки, в которой создастся проект. Slinn сам создаст папку, однако если она есть, то выдаст
предупреждение типа 
`www has already existed`.
Eго можно проигнорировать.

Затем необходимо перейти в папку с проектом и активировать созданное виртуальное окружение:

```Bash
cd www
venv\bin\activate
# или venv\Scripts\activate для Windows
```

Для запуска используйте команду:

```Bash
slinn run
```

```Bash
Apps: firstrun
Debug mode enabled
Smart navigation enabled

Starting server...
Press CTRL+C to quit
HTTP server is available on http://localhost:8080/
```

Открыв указанную ссылку в браузере, вы увидите подобное:
![localhost8080.png](localhost8080.png)

Это значит ваш проект создался успешно, и вообще все вы сделали хорошо.

## Строение проекта

**Дерево проекта**

```Text
├───manage.py
├───hcdp.py
├───htrf.py
├───project.json
├───start.bat
├───start.sh
├───Slinn.journal.log
├───firstrun/
├───templates_data
│   └───firstrun/
├───venv/
└───__pycache__/
```

- `manage.py` нужен для управления проектом и изменять его не стоит. При обновлении проекта файл перезаписывается;
- `hcdp.py` содержит обработчики для различных HTTP-кодов;
- `htrf.py` содержит обработчики для различных типов файлов;
- `project.json` содержит различные настройки;
- `start.bat` скрипт для запсука сервера на Windows;
- `start.sh` скрипт для запуска сервера на Linux/FreeBSD/MacOS и прочих Unix-подобных;
- `Slinn.journal.log` логи работы сервера.

Автоматически утанавливается приложение `firstrun` в соответствующую папку, а также его статические файлы в папку 
`templates_data/firstrun`.

Виртуальное окружение создается в папку venv.
В него автоматически пытаются установиться пакеты `slinn`, `dexir`, `pip`, `wheel`, `setuptools`.
Если хотя бы один из пакетов не будет успешно установлен, об этом скрипт создания проекта сообщит.

## Управление приложениями

В Slinn проект не может работать без приложений.
При запуске пустого проекта браузер выдаст ошибку о том, что сервер отправил пустой ответ.

Для создания приложения введите:

```Bash
slinn create-app localhost host=127.0.0.1 host=::1 host=:: host=localhost
```

Это создаст приложение в папке localhost. Само приложение будет называться аналогинчо. Также в конфиг проекта 
`project.json` будет добавлено это приложение.

`host=домен-или-IP-адрес` нужно для того, чтобы приложение работало только на определенных доменах и IP-адресах. 
Однако, этот параметр можно не указывать и приложение будет работать на всех доступных доменах и IP-адресах.

Для того, чтобы удалить приложение, введите:

```Bash
slinn delete-app firstrun
```

## Строение приложения

**Дерево минимального приложения**
```Text
├───__init__.py
├───app.py
├───config.json
└───__pycache__/
```

- `__init__.py` нужен для загрузки приложения, и изменять его не стоит;
- `app.py` является главным файлом приложения. Он содержит один `Dispatcher`;
- `config.json` нужен для настройки проекта. При создании кроме настройки `debug` в нем ничего нет.

## Шаблоны приложений
### Классические шаблоны
В Slinn на данный момент существует два классических шаблона приложений:
- firstrun - то самое приложение, которое устанавливается автоматически при создании проекта;
- example - это просто пример.

Классические шаблоны приложений находятся в `место-установки-slinn/templates/`.

В классических шаблонах есть папка `data`, в которой хранятся статические файлы.
При установке классического шаблона, эти файлы переносятся в `templates_data/название-шаблона`.

### Шаблоны-пакеты
Шаблоны-пакеты загружаются из репозиториев SPM (Пакетный менеджер Slinn).
Для установки шаблона-пакета:

```Bash
spm update  # обновите список пакетов
spm install fobox-app@fobox.core  # установите пакет с шаблоном
```

Чтобы установить шаблон, введите:

```Bash
slinn template example app
```
где `example` - имя шаблона; `app` - имя приложения.

## Конфигурация проекта

Проект конфигурируется в файле `project.json` .

Разберем пример конфигурационного файла, который создается автоматически.

```JSON
{
    "name": "Slinn",
    "async": true,
    "server_class": "AsyncServer",

    "host": "localhost",
    "port": 8080,
    
    "debug": true,

    "ssl": {
        "fullchain": false,
        "key": false
    },
    "apps": ["firstrun"],

    "smart_navigation": true,

    "timeout": 0.5,
    "max_bytes_per_receive": 65535,
    "max_header_size": 8192
}
```

- [name] название проекта;
- [async] запускать сервер асинхронно или нет;
- [server_class] класс сервера. Асинхронный - `AsyncServer`, синхронный - `Server`;
- [host] для указания IP-адрес, на котором будет работать сервер. Если указан домен, то он сконвертируется в IP-адрес;
- [port] для указания порта, который будет слушать сервер;
- [debug] если `false`, то debug-приложения не будут использоваться;
- [ssl][fullchain] файл с публичным сертификатом ssl;
- [ssl][key] файл с приватным ключом ssl;
- [apps] список приложений. Больший приоритет имеет то приложение, которое находится раньше по списку;
- [smart_navigation] использование технологии Smart Navigation;
- [timeout] таймаут подключения по умолчанию;
- [max_bytes_per_recieve] максимальное количество байт, которое примет сокет за один раз. Зависит от размера окна TCP;
- [max_header_size] максимальное количество байт на HTTP-заголовок запроса.
